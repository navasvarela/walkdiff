Review the change, not the diff.

Walkdiff is a review companion for GitHub pull requests and GitLab merge requests. It shows each changed function whole, where the rest of the code uses it, and what looks risky, then walks you through the parts that matter. It runs on your machine.

Why Walkdiff

A pull request's diff tells you which lines moved. A reviewer needs to know what changed in meaning, who depends on it, and where to look first. Most of that work happens in the reviewer's head, file by file, hunk by hunk. Walkdiff does the legwork so the reviewer's attention goes to judgement.

Reviewing a line diff
  • Hunks cut functions in half, with three lines of context.
  • A renamed or moved function looks like deleted code plus new code.
  • Formatting and comment edits look as important as logic changes.
  • Nothing says which callers the change affects, or which of them the PR left alone.
  • Files come in alphabetical order, whatever depends on what.
Reviewing with Walkdiff
  • Each changed function, method or type appears once, whole, before and after.
  • Renames, moves and formatting-only edits are recognised and folded away.
  • Each change lists its facts: parameters, return type, calls and error paths.
  • Every changed unit shows where the rest of the code still uses it.
  • A review path takes you through what matters most, one stop at a time.

What we believe

These ideas shape every feature, and say what Walkdiff will and won't do.

Units, not hunks

Code is reviewed as functions, methods and types, read from the syntax tree, so a change is seen the way its author thought about it.

A path through the change

Reviewers shouldn't have to plan their own route. The report opens on a brief and a review path that put the riskiest changes first, and says why each stop is there.

Say what was found, not a grade

Walkdiff reports findings and the checks that ran or didn't. It doesn't score a PR or approve it for you. Rules would rather stay quiet than raise a false alarm.

Your code stays yours

Analysis runs locally. Code leaves your machine only for the host you review on, and for an AI model if you ask for one. Every other network use is listed and can be switched off with --offline.

AI that shows its work

AI review is opt-in. Every statement must cite lines of the change, and Walkdiff checks each citation against what the model was shown, discarding the rest.

Fits how teams already work

Use it from the command line, a local app that tracks several reviews, or CI. Comments and approvals post back to GitHub and GitLab.

How a review goes

  1. Point it at a PR or MR. Walkdiff fetches only the merge base and head commits, and parses both versions of each changed file.
  2. Read the brief. What to check, how many changes need attention, and where to start.
  3. Walk the review path. Each stop shows one change with its code, callers, tests and findings, and says why it's on the path.
  4. Mark changes as reviewed and comment on exact lines. Everything else is one click away under All changes.
  5. Post your review to the PR from the app, or let CI leave a summary comment with a link to the report.

Languages

Changed units, callers, function metrics, risky-API rules and syntax highlighting work in:

  • Rust
  • TypeScript
  • JavaScript
  • Python
  • Go
  • Java
  • C
  • C++

Other files get a line diff, and the secret and sensitive-path rules still read them.

Where it's going

Walkdiff is an early release. The aim is a review companion that understands the change as well as its author does, in every language a team uses, and that stays honest about what it couldn't check.

Deeper language support

Dependency checks for Go and Java projects, and breaking-change detection for Java, C and C++, alongside Rust, TypeScript, Python and Go.

Reviewing stacks

Stacked PRs reviewed together, bottom first, with each PR's progress and what its host says now. This already works, and it will keep improving.

Fewer blind spots

Every check that can't run says so in the report. Each release turns more of those "not checked" lines into checks.
